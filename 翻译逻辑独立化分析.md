# 翻译逻辑独立化分析

## 📋 问题分析

**需求**：将翻译逻辑从"操作 2：字幕翻译生成"中独立出来，成为一个单独的按钮操作。

**当前状态**：翻译逻辑位于 `process_text()` 函数中，是字幕生成流程的一部分。

---

## 🔍 当前流程分析

### 现有流程

```python
def process_text():
    # 步骤 1: ASR 转录
    _2_asr.transcribe()

    # 步骤 2: 句子分割
    _3_1_split_nlp.split_by_spacy()
    _3_2_split_meaning.split_sentences_by_meaning()
```

## ✅ 独立化的可行性

### 结论：**完全可行，不会影响原有逻辑**

**理由**：

1. **输入输出都是文件**：所有模块通过文件交互，而非内存对象
2. **有明确的检查点**：使用 `@check_file_exists` 装饰器
3. **状态可持久化**：所有中间结果都保存到磁盘

## 🎯 独立化方案

### 方案一：完全独立（推荐）

将流程拆分为**三个独立的操作**：

```
操作 2a: ASR 和分割
    _2_asr.transcribe()
    _3_1_split_nlp.split_by_spacy()
    _3_2_split_meaning.split_sentences_by_meaning()

操作 2b: 翻译（新增）
    _4_1_summarize.get_summary()
    _4_2_translate.translate_all()

操作 2c: 字幕生成
    _5_split_sub.split_for_sub_main()
    _6_gen_sub.align_timestamp_main()
    _7_sub_into_vid.merge_subtitles_to_video()
```

---

### 方案二：保留原流程 + 新增独立按钮

```
操作 2: 字幕翻译生成（一键完成）
    原有逻辑不变

操作 2-单独: 仅翻译（新增）
    只执行 _4_1 + _4_2
    需要先完成操作 2a（或检测文件存在）
```

```python
def text_processing_section():

# ===== 拆分后的处理函数 =====

def process_transcription_and_segmentation():
    """操作 2a: 转录和分割"""
    with st.spinner(t("Using Whisper for transcription...")):
        _2_asr.transcribe()
    with st.spinner(t("Splitting long sentences...")):
        _3_1_split_nlp.split_by_spacy()
        _3_2_split_meaning.split_sentences_by_meaning()
    st.success(t("Transcription and segmentation complete! 🎉"))


def process_translation():
    """操作 2b: 翻译（独立操作）"""
    with st.spinner(t("Extracting terminology...")):
        _4_1_summarize.get_summary()

    # 可选：暂停编辑术语表
    if load_key("pause_before_translate"):
        st.info(t("⚠️ Please edit terminology in `output/log/terminology.json`, then click continue."))
        if st.button(t("Continue Translation"), key="continue_translate"):
            with st.spinner(t("Translating...")):
                _4_2_translate.translate_all()
            st.success(t("Translation complete! 🎉"))
            st.rerun()
    else:
        with st.spinner(t("Translating...")):
            _4_2_translate.translate_all()
        st.success(t("Translation complete! 🎉"))


def process_subtitle_generation():
    """操作 2c: 字幕生成"""
    with st.spinner(t("Processing and aligning subtitles...")):
        _5_split_sub.split_for_sub_main()
        _6_gen_sub.align_timestamp_main()
    with st.spinner(t("Merging subtitles to video...")):
        _7_sub_into_vid.merge_subtitles_to_video()
    st.success(t("Subtitle generation complete! 🎉"))
    st.balloons()


# ===== 清理函数 =====

def cleanup_step_2a():
    """清理步骤 2a 的输出文件"""
    import os
    files_to_remove = [
        _2_CLEANED_CHUNKS,
        _3_1_SPLIT_BY_NLP,
        _3_2_SPLIT_BY_MEANING
    ]
    for file in files_to_remove:
        if os.path.exists(file):
            os.remove(file)


def cleanup_step_2b():
    """清理步骤 2b 的输出文件"""
    import os
    files_to_remove = [
        _4_1_TERMINOLOGY,
        _4_2_TRANSLATION
    ]
    for file in files_to_remove:
        if os.path.exists(file):
            os.remove(file)
```

## 💡 独立化的优势

### 1. **用户可以重新翻译**

场景：用户对翻译结果不满意

```
原流程: 必须从头重新跑整个流程（包括 ASR，很耗时）
    ↓
新流程: 只需点击 "Redo Translation"，重新翻译即可（快速）
```

### 2. **支持编辑术语表**

场景：用户想自定义专业术语

```
步骤 1: 完成转录和分割
    ↓
步骤 2a: 生成术语表（暂停）
    ↓
用户手动编辑 terminology.json
    ↓
步骤 2b: 点击 "Continue Translation"
    ↓
步骤 3: 生成字幕
```

### 3. **可以切换目标语言**

场景：用户想生成多个语言版本

```
完成步骤 1（只需做一次）
    ↓
修改目标语言为"日语" → 执行步骤 2 → 执行步骤 3 → 下载日语字幕
    ↓
修改目标语言为"法语" → 执行步骤 2 → 执行步骤 3 → 下载法语字幕
    ↓
修改目标语言为"西班牙语" → ...
```

### 4. **可以预览翻译结果**

```
步骤 2 完成后:
    ✅ Translation complete!
    Total Lines: 234
    [Download Translation Results]  ← 下载 CSV 预览

用户可以先查看翻译质量，再决定是否继续生成字幕
```

### 5. **调试更方便**

```
开发者可以:
- 只测试翻译模块，无需每次都跑 ASR
- 使用固定的测试数据（split_by_meaning.txt）
- 快速迭代翻译 prompt
```

## ⚠️ 注意事项

### 1. 文件依赖检查

每个步骤都需要检查**前置条件**：

```python

if not os.path.exists(_3_2_SPLIT_BY_MEANING):
    st.warning(t("⚠️ Please complete Step 1 first"))
    return  # 阻止执行

# 步骤 3: 字幕生成
if not os.path.exists(_4_2_TRANSLATION):
    st.warning(t("⚠️ Please complete Step 2 first"))
    return
```

### 2. 清理函数要谨慎

```python
def cleanup_step_2b():
    """清理步骤 2b 的输出文件"""
```

## ✅ 最终结论

### 是否会影响原有逻辑？

**答案：不会影响核心逻辑，只需要调整 UI 和流程控制**

**理由**：

1. ✅ 所有模块都是**文件驱动**的，不存在内存状态依赖
2. ✅ 已有 `@check_file_exists` 装饰器确保文件存在
3. ✅ 各模块之间通过**固定文件路径**交互，耦合度低
4. ✅ 只需要拆分 `process_text()` 函数，核心处理逻辑无需改动

### 推荐做法

**方案 1（激进）**：完全拆分为 3 个独立步骤

- ✅ 最大化灵活性
- ❌ UI 变复杂

**方案 2（保守）**：保留原流程 + 新增"仅翻译"按钮

- ✅ 兼容性好
- ⚠️ 灵活性有限

**方案 3（折中，推荐）**：拆分为 3 步 + 提供"一键完成"按钮

- ✅ 平衡灵活性和易用性
- ✅ 用户可以选择快速模式或专业模式
